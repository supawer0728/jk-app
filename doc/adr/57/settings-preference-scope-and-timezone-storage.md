# 설정 동기화 범위 축소 및 시간대 저장 원칙

**상태**: 결정됨
**날짜**: 2026-07-07

## 맥락

이슈 #57은 원래 다크모드/햅틱 강도까지 포함한 전체 설정을 `users/{uid}.preference`에 동기화하는 것을 제안했다. 그러나 이슈 #56 구현 과정에서 이미 다크모드/햅틱을 `UserPreference`에서 제외하기로 결정했고(`doc/adr/56/user-profile-upsert-strategy.md`), 이번 이슈에서 이 결정을 재확인하면서 남은 범위(설정 화면의 언어/시간대 UI, 시간대 저장 원칙)를 정리해야 했다.

## 결정

1. **다크모드/햅틱은 기기 로컬 설정으로 유지**: `AppPreferences`(DataStore)가 계속 담당하고, `users/{uid}.preference`로 동기화하지 않는다. 기기마다 사용자가 진동/다크모드 경험을 다르게 느낄 수 있기 때문이다.
2. **`language`는 정보 표시 전용**: 설정 화면에 라디오 버튼 목록 UI를 두되 "한국어" 단일 옵션만 제공한다. 실제 로케일 전환 로직은 구현하지 않는다(향후 다국어 지원 시 옵션을 추가할 수 있는 구조만 마련).
3. **`timeZone`은 고정 목록(Asia/Seoul, UTC) 중 선택**: 변경 시 `UserRepository.updatePreference`로 Firestore에 fire-and-forget 반영한다. 현재 앱에는 시간대 변환이 필요한 `Instant`/`Timestamp` 필드가 없어 실제 변환 로직은 아직 적용되지 않지만, 값 자체는 저장·동기화된다.
4. **시간대 저장 원칙**: 향후 `Instant`/`Timestamp` 기반 필드(예: 할 일 마감 시각)가 추가되면 Firestore에는 항상 UTC로 저장하고, 화면 표시 시점에만 `ZoneId.of(preference.timeZone)`으로 변환한다. 기기 로컬 시간대가 아닌 사용자가 설정한 `timeZone` preference를 기준으로 변환한다.

## 근거

- 다크모드/햅틱 제외는 이슈 #56에서 이미 검증된 결정이며, 이번 세션에서 이슈 코멘트로 재확인했다(기기별로 다르게 유지되길 원하는 사용자 경험).
- `language`를 완전히 숨기지 않고 단일 옵션 UI로 노출한 이유는, 이후 다국어를 지원하게 됐을 때 옵션만 추가하면 되는 구조를 미리 마련해두기 위함이다.
- `timeZone`을 지금 당장 쓰이지 않음에도 UI로 노출한 이유는, 이 값이 이미 로그인 시점에 Firestore에 기본값으로 저장되고 있고(#56), 향후 시간 기반 기능이 추가될 때 사용자가 미리 값을 맞춰둘 수 있게 하기 위함이다.

## 검토한 대안

- **이슈 #57을 통째로 "작업 없음"으로 종료**: 다크모드/햅틱 동기화가 이미 기각되었고 language/timeZone 기본값도 이미 저장되고 있어 검토했으나, 사용자가 값을 직접 바꿀 UI가 없다는 공백이 남아 채택하지 않았다.
- **`timeZone`을 전체 `ZoneId` 목록에서 자유롭게 선택**: 이 앱은 2인만 사용하고 현재는 한국 표준시만 사실상 필요해 과한 범위로 판단, 고정된 2개 옵션(Asia/Seoul, UTC)으로 축소했다.

## 예상 결과

- 설정 화면에 언어/시간대 섹션이 추가되고, 로그인한 사용자의 `users/{uid}.preference`를 실시간 구독해 표시한다.
- 로그아웃 상태에서는 `UserPreference()` 기본값을 보여주고 변경은 무시한다(반영할 uid가 없으므로).
- 향후 `Instant` 기반 필드가 생기면 이 ADR의 시간대 저장 원칙(UTC 저장, 표시 시점 변환)을 그대로 따른다.
