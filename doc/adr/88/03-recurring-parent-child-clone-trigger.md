# 반복 부모의 자식 복제는 목록 사이클 완료 경로에서만 확인 다이얼로그로 유발한다

**상태**: 결정됨
**날짜**: 2026-07-18

## 맥락

반복(RecurrenceRule)을 가진 부모 할일이 한 회차를 완료하면 `dueAt`이 다음 회차로 전진하고
상태가 `NOT_STARTED`로 리셋된다(ADR 52 계열). 부모가 자식을 가진 경우, 다음 회차에서도 같은
체크리스트(자식)를 반복하고 싶을 수 있으므로 "이전 회차의 자식을 새 회차용으로 복제할지"를
사용자에게 물어야 한다.

부모 완료는 여러 경로에서 일어난다. (a) 목록 화면에서 사용자가 상태를 진행시키는
`advanceStatus` 경로, (b) 마감 리마인더 등 백그라운드에서 완료되는 경로. 어느 경로에서 복제를
유발할지 정해야 했다.

## 결정

**목록 사이클 완료 경로(`TodoScreen`의 `advanceStatus`)에서만** 자식 복제 확인 다이얼로그를
띄운다. 리마인더 등 **백그라운드 완료 경로는 복제 대상에서 제외**한다.

## 근거

- **사용자 확인이 전제**: 복제는 "물어보고 결정"하는 동작이다. UI 컨텍스트가 있는 목록 완료
  경로에서만 다이얼로그를 띄울 수 있고, 백그라운드에는 사용자에게 물을 화면이 없다.
- **무단 파생 쓰기 회피**: 백그라운드에서 자동 복제하면 사용자 의사 없이 자식 문서가 늘어난다.
  또 복제는 파생 쓰기라 "단일 변경당 푸시 ≤1건"(ADR 88/02) 아래 무알림이어야 하는데, 백그라운드
  자동 복제까지 얹으면 완료 시점의 파생 연쇄가 더 복잡해진다.
- **경로 단일화**: 복제 트리거를 목록 완료 한 곳으로 좁히면, 복제 여부·개수·무알림 규칙을 한
  경로에서만 검증하면 된다.

## 검토한 대안

- **모든 완료 경로에서 복제(백그라운드 포함)**: 백그라운드에는 확인 UI가 없어 자동 복제할 수밖에
  없고, 사용자 의사 없는 문서 증가·파생 연쇄 확대를 부른다. 제외.
- **완료 시 자동 복제, 확인 없음**: 매 회차 자식이 자동 생성돼 원치 않는 반복까지 복제된다.
  가벼운 체크리스트 성격과 맞지 않아 제외.
- **복제 없음(자식은 첫 회차만)**: 반복 체크리스트 요구를 충족하지 못한다. 사용자에게 선택권을
  주는 편이 낫다고 판단해 제외.

## 예상 결과

- `TodoScreen`의 `advanceStatus` 경로에서 반복 부모가 완료될 때만 복제 확인 `AlertDialog`가 뜬다.
- 복제 실행은 `addSubTodoItem(..., notify=false)`로 무알림 처리된다(ADR 88/02).
- 리마인더 등 백그라운드 완료 경로는 복제 다이얼로그를 거치지 않는다.
- 복제 트리거 규칙의 현재-사실은 `doc/dev/todo/FEATURE.md`에 반영한다.
