# 자식 TODO를 별도 컬렉션 없이 `todo-items` 단일 컬렉션에 `type`+`mainTodoId`로 표현한다

**상태**: 결정됨
**날짜**: 2026-07-18

## 맥락

이슈 #88에서 할일에 1-depth 자식 항목(체크리스트성 하위 작업)을 추가한다. 자식은
부모 할일에 종속된 가벼운 항목으로, 실제 요구는 "제목·담당자·메모"만 관리하면 충분하고
마감·리마인더·반복·우선순위 같은 스케줄링 속성은 부모에게만 있으면 된다.

부모-자식 관계를 어디에, 어떤 구조로 저장할지 정해야 했다. 선택지는 (a) `todo-items`
하위 서브컬렉션, (b) `todo-sub-items` 같은 별도 최상위 컬렉션, (c) 기존 `todo-items`
단일 컬렉션에 종류·부모참조 필드를 추가하는 방식이었다. 기존 `todo-items`는 이미
실시간 리스너(`addSnapshotListener`) 하나로 전체 목록을 구독하는 구조이고, 리마인더·
반복·담당자 푸시 등 여러 파생 로직이 이 컬렉션 위에 얹혀 있다.

## 결정

기존 `todo-items` 단일 컬렉션을 유지하고, `TodoItem`에 두 필드를 추가해 계층을 표현한다.

- `type: TodoType` — `MAIN`(기본, 독립 항목) | `SUB`(자식 항목). `type` 필드가 없는
  레거시 문서는 `MAIN`으로 간주한다(`TodoType.fromNameOrDefault`).
- `mainTodoId: String?` — `SUB`일 때 부모 문서 id를 가리키는 자기참조. `MAIN`이면 `null`.

계층은 1-depth로 제한한다. `SUB`는 다시 부모가 될 수 없다. 자식은 제목·담당자·메모만
관리하고 `dueAt`/리마인더/반복/우선순위는 갖지 않는다(폼에서도 노출하지 않는다).
부모 자동완료(자식이 모두 DONE이면 부모도 DONE)는 두지 않는다.

## 근거

- **단일 컬렉션 + 자기참조**: 부모·자식이 같은 컬렉션에 평탄하게 저장되므로 기존 실시간
  리스너 하나로 부모·자식을 함께 구독하고, 화면에서 `mainTodoId`로 필터링해 부모별 자식을
  그려낼 수 있다. 서브컬렉션이면 부모마다 별도 리스너가 필요하거나 collectionGroup 쿼리를
  써야 해 실시간 동기화 구조가 복잡해진다.
- **레거시 역호환**: `type` 기본값 `MAIN` + `fromNameOrDefault` 폴백으로, 필드가 없는 기존
  문서를 마이그레이션 없이 `MAIN`으로 읽는다. 첨부·설정 등 다른 도메인에서 써 온 기본값
  역호환 관례(ADR 18/01 등)와 동일하다.
- **속성 최소화**: 자식에 스케줄링 속성을 두지 않으면 리마인더 예약·반복 전진 로직이 부모
  경로에만 존재해, 자식이 이 로직에 끼어들어 생기는 예외 케이스를 원천 차단한다.
- **부모 자동완료 배제**: 자동완료를 넣으면 "자식 완료 → 부모 상태 변경 → 파생 쓰기·푸시"라는
  연쇄가 생겨 이슈 #88의 "단일 변경당 푸시 ≤1건" 원칙(ADR 88/02)과 충돌한다. 부모 완료는
  사용자가 명시적으로 하도록 남긴다.

## 검토한 대안

- **별도 최상위 컬렉션(`todo-sub-items`)**: 부모 목록과 자식 목록을 각각 구독해 앱에서 조인해야
  하고, cascade 삭제·완료 시 두 컬렉션을 함께 다뤄야 한다. 실시간 리스너·트랜잭션 범위가
  넓어져 이득 없이 복잡도만 늘어 제외.
- **`todo-items/{id}/subs` 서브컬렉션**: 부모별 리스너 분산 또는 collectionGroup 인덱스가
  필요하고, 기존 단일 리스너 구독 모델을 깨뜨린다. 제외.
- **자식에 전체 속성 부여(부모와 동형)**: 리마인더·반복 로직이 자식까지 확장돼 표면적이 커지고,
  실제 사용 시나리오(가벼운 하위 체크 항목)와 맞지 않아 제외.

## 예상 결과

- `TodoItem`에 `type`·`mainTodoId`가 추가되고, `TodoFirestoreRepositoryImpl`의 companion
  상수·직렬화가 두 필드를 다룬다. 현재-사실은 `doc/dev/todo/DOMAIN.md`에 반영한다.
- 목록 화면은 `state.items`에서 `mainTodoId`로 자식을 필터링해 부모 아래 펼침 영역으로 그린다.
  자식 전용 폼은 제목·담당자·메모만 노출한다.
- cascade(부모 완료→자식 DONE, 부모 삭제→자식 삭제)와 반복 복제 규칙이 이 모델 위에서
  성립한다. 각 규칙의 트리거·알림 정책은 ADR 88/02·88/03에서 정한다.
