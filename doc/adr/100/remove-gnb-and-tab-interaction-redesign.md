# 상단 GNB 제거·하단 탭 상호작용 재설계 (ADR 41 대체)

**상태**: 결정됨 (ADR 41 대체)
**날짜**: 2026-07-18

## 맥락

이슈 #100은 콘텐츠(주 화면) 영역을 최대한 넓게 확보하기 위해 상단 GNB와 하단 탭 UI를
전면 개편한다. 현재 구조는 다음과 같다.

- `MainScreen`에 `TopAppBar`(상단 GNB)가 있고, 여기에 프로필 아바타·화면 타이틀과
  `설정`·`로그아웃` 진입점이 들어 있다.
- 하단 탭은 아이콘+텍스트로 표시되고, `MainTab` enum(HOME/ASSET/DIARY/TODO/CALENDAR)
  5개가 콘텐츠 탭이다.
- 탭 순서 커스터마이징은 **하단바에서 직접** 이뤄진다. 하단바를 세로로 스와이프해
  `TabOrderPanel`(스와이프 업 패널)을 열고, jiggle/드래그로 재배열한다.
  이 방식은 [ADR 41](../41/tab-order-firestore-schema.md)에서
  결정한 것이다(스와이프 패널 노출 + 인라인 드래그앤드롭, `MAIN_TAB_ROW_SIZE`(5) 노출).

이 상호작용은 상단 GNB와 하단 세로 스와이프 패널이 각각 화면 세로 공간을 차지하고,
탭 재배열이 일상 조작(탭 전환)과 같은 위치에서 일어나 오조작 여지가 있다.
#100은 이를 걷어내고 콘텐츠 영역을 넓히며, 탭 재배열은 설정으로 격리한다.

## 결정

ADR 41이 정한 하단 탭 상호작용(세로 스와이프 패널 + 인라인 재배열)을 아래로 대체한다.
단, ADR 41의 **`tab-orders` Firestore 스키마(문서ID=uid, `tabs: List<String>`,
`MainTab.name` 순서 저장, 미존재 탭 무시·신규 탭 뒤 자동 추가)와 별도 `TabOrderRepository`
분리는 그대로 유지**한다. 바뀌는 것은 "재배열을 어디서·어떻게 하는가"와 상단/하단 셸이다.

### 1. 상단 GNB(TopAppBar) 완전 제거
`MainScreen`의 `TopAppBar`를 제거한다. 프로필 아바타·화면 타이틀도 함께 사라지고,
그만큼 콘텐츠 영역이 위로 확대된다.

### 2. `설정`·`로그아웃`을 하단 '액션 탭'으로 흡수
GNB에 있던 `설정`·`로그아웃` 진입점을 하단 탭으로 옮긴다. 단 이 둘은 콘텐츠 화면을
가진 일반 탭(`MainTab`)이 아니라 **액션 탭**으로 특수 취급한다.
- 하단 탭 전체 노출 순서: `홈 · 자산관리 · 육묘일기 · TODO · 캘린더 · 로그아웃 · 설정`.
- 앞 5개(`MainTab`)는 선택 시 콘텐츠 화면을 바꾸는 기존 방식 그대로다.
- `로그아웃`·`설정`은 `MainTab` enum에 넣지 않는다. 콘텐츠 화면이 없으므로 선택 상태로
  남지 않고, 누르면 각각의 액션(설정 화면 이동 / 로그아웃 확인 다이얼로그)만 수행한다.
- `로그아웃` 탭을 누르면 확인 다이얼로그("정말 로그아웃하시겠습니까?")를 띄우고,
  확인 시에만 `viewModel.signOut()`을 호출한다. 취소하면 원래 선택 탭이 유지된다.

### 3. 하단 탭 아이콘 제거(텍스트 전용) + 시각 보완
하단 탭에서 아이콘을 제거하고 텍스트 라벨만 표시한다. 텍스트만 남아 구분이 약해지므로
탭 간 **구분선**을 두고, **현재 선택된 탭**은 색을 더 짙게 표시한다.

### 4. 탭 순서 편집을 설정 화면으로 이동
하단바 인라인(jiggle/드래그) 재배열을 제거하고, `설정`에 `탭 순서 변경` 항목을 추가한다.
누르면 별도 화면으로 이동해 **드래그앤드롭**으로 순서를 바꾸고, 하단의 **적용/취소**로
확정한다.
- 재배열 대상은 **콘텐츠 탭(`MainTab`: 홈~캘린더)만**이다. 액션 탭(로그아웃/설정)은
  대상이 아니며 항상 콘텐츠 탭 뒤에 고정 노출된다.
- `취소`: 변경을 버리고 이전 화면으로 돌아간다.
- `적용`: 변경이 없으면 no-op, 있으면 `tab-orders`(ADR 41 스키마)에 저장하고 하단 탭에
  즉시 반영한다.
- `tab-orders` 스키마와 `TabOrderRepository`는 ADR 41 그대로 재사용한다.

### 5. 하단 탭 노출 방식을 가로 슬라이드로 변경
기존 '세로 스와이프 업 패널'(`TabOrderPanel`)을 제거하고, 하단 탭 줄을 **가로 슬라이드**로
바꾼다. `MAIN_TAB_ROW_SIZE`(5)개를 한 번에 보여주고, 나머지(로그아웃·설정 등)는 옆으로
스크롤해 접근한다. 세로 스와이프 손잡이·패널·jiggle 관련 UI는 제거한다.

## 근거

- 상단 GNB와 하단 세로 스와이프 패널은 각각 화면 세로 공간을 소비한다. GNB를 없애고
  재배열을 설정으로 격리하면 일상 조작(탭 전환) 화면이 단순해지고 콘텐츠가 넓어진다.
- 탭 재배열은 드물게 일어나는 설정성 작업이다. 이를 일상 조작과 같은 위치(하단바)에서
  하면 오조작 여지가 있어, 명시적으로 진입하는 설정 화면(적용/취소 확정)으로 옮기는 편이
  실수·되돌리기 측면에서 안전하다.
- `설정`·`로그아웃`을 `MainTab` enum에 넣지 않고 액션 탭으로 분리한 이유: 이 둘은 콘텐츠
  화면이 없어 "선택 상태"라는 개념이 성립하지 않는다. enum에 섞으면 `when(selectedTab)`
  분기와 선택 하이라이트가 불필요하게 복잡해지고, 재배열 대상 필터링도 어려워진다.
- `tab-orders` 스키마와 `TabOrderRepository`를 유지하는 이유: 데이터 영속화 계층은
  이번 UX 변경과 직교한다. 재배열 UI만 옮길 뿐 저장 구조를 바꿀 이유가 없어, 데이터
  마이그레이션 없이 안전하게 UI만 교체할 수 있다.

## 검토한 대안

- **GNB는 두고 아이콘/순서변경만 제거**: 콘텐츠 영역 확대 효과가 제한적이고, 상단·하단에
  진입점이 분산돼 정보 구조가 어중간해진다. #100의 핵심 동기(영역 확대)를 못 살려 제외.
- **`설정`·`로그아웃`도 `MainTab` enum에 포함**: 열거형이 단순해 보이지만, 콘텐츠 없는
  탭에 선택 상태·`when` 분기가 생기고 재배열 대상에서 매번 제외해야 해 오히려 복잡.
  액션 탭 특수 취급이 각 관심사를 깔끔히 분리한다.
- **세로 스와이프 패널 유지(ADR 41 방식 존치)**: 상단 GNB 제거만으로도 영역은 늘지만,
  텍스트 전용·가로 슬라이드 요구와 상충하고 세로 공간을 계속 소비해 제외.
- **`tab-orders` 스키마 변경(액션 탭까지 순서 저장)**: 액션 탭은 순서 고정이므로 저장
  대상이 아니다. 스키마를 건드리면 마이그레이션 부담만 생겨 제외.

## 예상 결과

- `MainScreen`에서 `TopAppBar`가 사라지고 콘텐츠가 상단까지 확대된다.
- 하단 탭은 텍스트 전용·구분선·선택 강조로 표시되고, 가로 슬라이드로 5개 초과 탭에
  접근한다. `로그아웃`·`설정`은 액션 탭으로 동작한다(로그아웃은 확인 다이얼로그 경유).
- 탭 순서 변경은 설정 화면의 드래그앤드롭 + 적용/취소로만 가능하고, 대상은 콘텐츠 탭에
  한정된다. 저장은 기존 `tab-orders`(ADR 41 스키마)를 그대로 사용한다.
- ADR 41이 도입한 세로 스와이프 패널·인라인 jiggle/드래그(`TabOrderPanel`,
  `computeNewIndex`/`computeOffsetAfterMove`, 하단바 스와이프 제스처)는 제거되거나
  설정 화면용으로 재구성된다. `TabOrderViewModel.mergeTabOrder`·편집 중 스냅샷 무시
  로직은 설정 화면 재배열 흐름에서 계속 활용한다.

## 후속 보완 (2026-07-19)

이 ADR의 "2. `설정`·`로그아웃`을 하단 '액션 탭'으로 흡수" 중 **로그아웃 부분을 철회**한다.
사용자 피드백에 따라 로그아웃은 하단 탭이 아니라 **설정 화면 내 항목**으로 옮긴다. 누르면
동일한 확인 다이얼로그를 거쳐 `AuthViewModel.signOut()`을 호출한다. 이로써:

- 하단바 가운데 스크롤 영역은 홈을 제외한 순수 콘텐츠 탭(자산관리·육묘일기·TODO·캘린더) 4개만
  남는다. 콘텐츠 탭만 남으므로 `Content`/`Action`을 구분하던 `BottomTabItem` sealed 타입은
  제거하고 `MainTab`을 직접 사용한다(dead 분기 정리).
- 설정 아이콘은 그대로 하단바 오른쪽에 고정된다(이 부분은 유지).

근거: 로그아웃은 드물고 되돌릴 수 없는 조작이라 일상 탭 영역보다 설정 화면에 두는 편이
오조작을 줄인다. `설정` 진입점을 하단바 아이콘으로 유지하는 결정과는 상충하지 않는다.
